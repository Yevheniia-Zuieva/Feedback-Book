# Книга відгуків (Javalin REST API)

Проєкт реалізує багатомодульний вебдодаток для управління каталогом книг та додавання/перегляду відгуків до них. Архітектура побудована за багатомодульним принципом Maven (`core`, `persistence`, `web`).

У цій версії вебрівень мігровано з Jakarta Servlet API та JSP на мікрофреймворк **Javalin**. Додаток працює за принципом **REST API** з передачею даних у форматі JSON, а як клієнт використовується статичний HTML/JS. Для збереження даних застосовується вбудована база даних H2 (JDBC).

## Технологічний стек

* **JDK:** 21
* **Maven:** 3.9.16
* **Вебфреймворк / Сервер:** Javalin 6.2.0 (на базі вбудованого Jetty)
* **JSON:** Jackson (`jackson-databind`, `jackson-datatype-jsr310`)
* **СУБД:** H2 (вбудована, файловий режим)
* **Логування:** SLF4J + Logback
* **Тестування:** JUnit 5, ArchUnit
* **Архітектура:** Багатомодульний проєкт із розділенням на Domain/Ports/Adapters.

## Структура проєкту

Проєкт розділено на три незалежні модулі для чіткого розділення відповідальності (Separation of Concerns):

```text
MPF_Labs/
├── pom.xml (батьківський конфіг, об'єднує модулі)
├── core/         # Бізнес-логіка, доменні моделі та порти (ізольований модуль)
│   └── src/main/java/sumdu/edu/ua/core/
├── persistence/  # Робота з БД H2, реалізація портів доступу до даних (залежить від core)
│   └── src/main/java/sumdu/edu/ua/persistence/
└── web/          # REST-контролери Javalin, DTO, Middleware, конфігурація та статичний клієнт (залежить від core та persistence)
    └── src/main/java/sumdu/edu/ua/web/
```

## Бізнес-правила

* **Видалення відгуків:** згідно з доменним правилом у `CommentService`, відгук до книги дозволено видаляти лише протягом 24 годин з моменту його створення.

## Команди запуску

Оскільки проєкт складається з трьох модулів, збірку потрібно виконувати з кореневої директорії, а запуск сервера — з модуля `web`.

1. Повна збірка проєкту та виконання тестів (у корені):

   ```bash
   mvn clean install
   ```

2. Запуск додатка Javalin (через `exec-maven-plugin`):

   ```bash
   mvn -pl web exec:java
   ```

Після успішного запуску вебклієнт буде доступний у браузері за адресою: `http://localhost:8080/`

## Архітектурні тести (ArchUnit)

У проєкті реалізовано автоматичну перевірку архітектури шарів за допомогою бібліотеки ArchUnit. Тести гарантують дотримання наступних правил ізоляції:

* Модуль `web` не має прямої залежності від `persistence` (за винятком конфігураційного класу `Beans`).
* Модуль `core` (бізнес-логіка) є повністю незалежним і не посилається на `web` чи `persistence`.
* Модуль `persistence` не має залежностей від `web`.

Запуск усіх перевірок виконується командою в корені проєкту:

```bash
mvn test
```

## Логування, Middleware та обробка помилок

* **Middleware (`app.before`, `app.after`):** здійснює автоматичне логування всіх вхідних HTTP-запитів та статусів відповідей у консоль.
* **Рівні логування:**

  * `INFO`: фіксація вхідних запитів (`-> Request`), статусів відповідей (`<- Response`), створення та видалення відгуків.
  * `WARN`: клієнтські помилки статусу `4xx`.
  * `ERROR`: перехоплені необроблені винятки статусу `5xx` із виведенням stack trace.
* **Централізована обробка винятків (`app.exception`):** перехоплює помилки виконання та повертає відповідь у стандартизованому JSON-форматі:

```json
{
  "error": "Internal server error",
  "message": "деталі винятку"
}
```

## База даних

* **СУБД:** H2 (працює в локальному файловому режимі).
* **URL підключення:** `jdbc:h2:file:./data/guest;AUTO_SERVER=TRUE`
* **Шлях до файлу БД:** `./data/guest.mv.db` (створюється автоматично при першому запуску).

## Список REST API ендпоїнтів

### Статичний клієнт

* **`GET /`**

  * Перенаправляє на статичну HTML-сторінку (`/index.html`), яка відображає каталог книг через `fetch()`.

### API Книг (`BooksController`)

* **`GET /api/books`**

  * Повертає список книг у форматі JSON. Підтримує пагінацію (`page`, `size`) та пошук за назвою/автором (`q`).
  * *Приклад:* `GET /api/books?q=java&page=0&size=10`
* **`GET /api/books/{id}`**

  * Повертає інформацію про конкретну книгу за її ID.
  * *Приклад:* `GET /api/books/1`
* **`POST /api/books`**

  * Створює нову книгу.
  * **Тіло запиту (JSON):** `{"title": "Clean Code", "author": "Robert Martin", "pubYear": 2008}`

### API Коментарів (`CommentsController`)

* **`GET /api/comments?bookId={id}`**

  * Повертає список коментарів до вказаної книги у форматі JSON з підтримкою дат `Instant`.
  * *Приклад:* `GET /api/comments?bookId=1`
* **`POST /api/comments`**

  * Створює новий коментар до книги (повертає статус `201 Created`).
  * **Тіло запиту (JSON):** `{"bookId": 1, "author": "Євгенія", "text": "Чудова книга!"}`
* **`DELETE /api/comments/{id}?bookId={bookId}`**

  * Видаляє коментар за його ID з перевіркою доменного правила 24 годин.
