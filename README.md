# Книга відгуків

Проєкт реалізує багатомодульний вебдодаток на базі Jakarta EE для управління каталогом книг та перегляду/додавання відгуків до них. Архітектура побудована за багатомодульним принципом Maven (`core`, `persistence`, `web`). Для обробки HTTP-запитів використовуються сервлети, а для збереження даних — вбудована база даних H2 (JDBC).

## Технологічний стек

* **JDK:** 21
* **Maven:** 3.9.16
* **Сервер:** Jetty 11 (Servlet 5.0 / Jakarta EE 9+)
* **СУБД:** H2 (вбудована, файловий режим)
* **Логування:** SLF4J + Logback
* **Тестування:** JUnit 5, ArchUnit
* **Архітектура:** Багатомодульний проєкт із розділенням на Domain/Ports/Adapters.

## Структура проєкту

Проєкт розділено на три незалежні модулі для чіткого розділення відповідальності (Separation of Concerns):

```text
MPF_Labs/
├── pom.xml (батьківський конфіг, об'єднує модулі)
├── core/         # Бізнес-логіка, доменні моделі та порти (ізольований модуль)
│   └── src/main/java/sumdu/edu/ua/core/
├── persistence/  # Робота з БД H2, реалізація портів доступу до даних (залежить від core)
│   └── src/main/java/sumdu/edu/ua/persistence/
└── web/          # HTTP-сервлети, фільтри, конфігурація та JSP-сторінки (залежить від core та persistence)
    └── src/main/java/sumdu/edu/ua/web/
```

## Бізнес-правила

* **Видалення відгуків:** згідно з доменним правилом у `CommentService`, відгук до книги дозволено видаляти лише протягом 24 годин з моменту його створення.

## Команди запуску

Оскільки проєкт складається з трьох модулів, збірку потрібно виконувати з кореневої директорії, а запуск сервера — виключно з модуля `web`.

1. Повна збірка проєкту (виконується в корені):

```bash
mvn clean install
```

2. Запуск вбудованого сервера Jetty:

```bash
mvn -pl web jetty:run
```

Після успішного запуску додаток буде доступний у браузері за адресою: `http://localhost:8080/books`

## Архітектурні тести (ArchUnit)

У проєкті реалізовано автоматичну перевірку архітектури шарів за допомогою бібліотеки ArchUnit. Тести гарантують дотримання наступних правил ізоляції:

* Сервлети знаходяться виключно у модулі `web`.
* Модуль `web` не має прямої залежності від `persistence` (за винятком фабрики ініціалізації `Beans`).
* Модуль `core` (бізнес-логіка) є повністю незалежним і не посилається на `web` чи `persistence`.
* Модуль `persistence` не має залежностей від `web`.

Запуск усіх перевірок виконується командою в корені проєкту:

```bash
mvn test
```

## Логування та обробка помилок

* **Рівні логування:**

  * `INFO`: фіксація успішного створення та видалення відгуків (із ключовими атрибутами).
  * `WARN`: клієнтські помилки статусу `4xx` (невалідні параметри, відсутні ресурси).
  * `ERROR`: внутрішні винятки сервера статусу `5xx` із виведенням повного stack trace.
* **ErrorFilter:** перехоплює неперехоплені винятки та повертає відповідь у стандартизованому JSON-форматі:

```json
{
  "error": "Internal Server Error",
  "message": "деталі помилки"
}
```

## База даних

* **СУБД:** H2 (працює в локальному файловому режимі).
* **URL підключення:** `jdbc:h2:file:./data/guest;AUTO_SERVER=TRUE`
* **Шлях до файлу БД:** `./data/guest.mv.db` (створюється автоматично при першому запуску).

## Список ендпоїнтів

### Сторінки (HTML/JSP)

* **`GET /books`**

  * Головна сторінка каталогу книг. Підтримує параметри пошуку та пагінації: `q` (пошуковий запит), `page`, `size`.
* **`GET /comments?bookId={id}`**

  * Детальна сторінка книги. Містить динамічний список коментарів та форму додавання нового відгуку.

### API (Сервлети)

* **`POST /comments`**

  * Додає новий відгук до вказаної книги.
  * **Параметри форми:** `bookId`, `author`, `text`.
* **`POST /comments` (Видалення)**

  * Видаляє відгук з перевіркою правила 24 годин.
  * **Параметри форми:** `bookId`, `commentId`, `_method=delete`.
* **`GET /api/books`**

  * Повертає список книг у форматі JSON з підтримкою пагінації (`page`, `size`) та фільтрації (`q`).
* **`POST /api/books`**

  * Створює нову книгу через JSON-запит (`title`, `author`, `pubYear`).
